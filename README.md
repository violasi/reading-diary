# 阅读打卡日记

家长在 Mac 上用 skill 把阅读素材做成任务包，传到孩子的安卓平板，孩子自由地读，家长听录音打星。
**没有关卡**：翻页、听、录音都由孩子自己决定什么时候用；点「读完了」就算今天读过。
**零后端、零云服务、永久免费。**

设计文档：[技术调研](docs/技术调研.md)｜[架构设计](docs/架构设计.md)｜[孩子端设计](docs/孩子端设计.md)｜[设计稿](docs/mock/kid-design.html)

## 跑起来

```bash
npm install && npm run dev
```

打开 http://localhost:5181 。首次进入没有任务包，点右下角「爸爸妈妈」选一个 `.rdpkg` 导入。

### 关于素材

仓库里**不含任何版权素材**：绘本/分级读物的 PDF、打好的 `.rdpkg`、以及奥特曼立绘都没有入库。

陪读角色的图请自备，放到 `public/images/ultraman/`，文件名对应 `src/data/heroes.ts`
里的 id（默认只用到 `taro.png`）。**缺图不影响使用** —— App 会静默降级，不会显示碎图标。

阅读素材同理：把自己的 PDF 放在项目根目录，按下面的流程出任务包。

## 家长端：出任务包

不是 App，是一个 Claude Code skill。详见 [SKILL.md](.claude/skills/reading-pack/SKILL.md)。

```bash
# 1. 从 PDF 抠每页音频 + 渲染整页图
uv run --quiet --with pymupdf python .claude/skills/reading-pack/scripts/extract_pdf.py "某本书.pdf" build/some-book
# 2. 写 plans/<日期>.plan.json（挑正文页），然后打包
python3 .claude/skills/reading-pack/scripts/build_pack.py plans/2026-07-31.plan.json packs
```

一天一个包，一本书一个 `piece`，篇数不限。

## 上平板用

### 方式一：装 APK（推荐，录音最稳）

已经打好了：`out/阅读打卡日记-debug.apk`（约 4.5 MB）。用数据线连上平板后：

```bash
~/Library/Android/sdk/platform-tools/adb install -r "out/阅读打卡日记-debug.apk"
```

或者把 apk 拷到平板上直接点开装（要先允许「未知来源」）。已锁竖屏，
`RECORD_AUDIO` / `MODIFY_AUDIO_SETTINGS` 都声明好了，首次录音时系统会弹一次权限。

重新打包 —— **一条命令，别手动分步跑**：

```bash
npm run apk
```

`scripts/build-apk.sh` 会依次做完 构建前端 → `cap sync` → `assembleDebug` → 拷到 `out/`，
中间还会校验同步进原生工程的产物和 `dist` 一致。分步手动跑最容易只执行了
`npm run build` 就去装 APK，装到的其实是上一次的前端产物（踩过一次）。

构建注意（都已配好，写下来免得以后踩）：
- 本机没有 cmdline-tools，装不了新 SDK 组件，所以钉在 `compileSdk 34` + `build-tools 34.0.0`
- Gradle wrapper 指向本机已有的 **8.14.3**，不用再下 Capacitor 默认的 8.2.1（200 MB）
- `android/build.gradle` 里给**顶层和所有子工程**都配了阿里云镜像。
  少了子工程那一段，`capacitor-android` 会直连 `dl.google.com`，国内网络下
  常在 TLS 握手就被掐断（实测就是这么失败的）

### 升级 App 而不丢孩子的阅读记录

安卓只允许**同一签名**的包原地覆盖升级。签名一变就必须先卸载，而卸载会连着
IndexedDB 一起清掉 —— 孩子所有的进度、录音、打卡日历全没。所以：

```bash
# 升级：-r 是就地覆盖，数据保留
~/Library/Android/sdk/platform-tools/adb install -r "out/阅读打卡日记-debug.apk"
```

**要备份 `android/keystore/reading-diary.keystore`。** 这个文件不入库（公开仓库不能放密钥），
但它决定了以后打的包能不能覆盖升级。换机器、重装系统、清了 `~/.android/` 之后，
gradle 会生成一个新密钥 —— 签名就变了，只能卸载重装。把它跟项目备份放在一起。

密钥找不到时构建会**直接失败并说明原因**，不会悄悄用新密钥签出一个装不上去的包。

如果真的丢了密钥：只能卸载重装，那之前的记录就没了。装之前可以先在家长页
把重要的星星记下来 —— 目前没有导出功能（单设备场景当初判断用不上）。

数据结构层面也做了保障：`loadProgress` 读出来一律补齐字段，以后给进度加新字段，
老记录会自动拿到默认值；真要改键的形状，在 `db.ts` 的 `migrate()` 里加一步并把
`SCHEMA_VERSION` +1。

### 方式二：静态托管（⚠️ 必须 HTTPS）

**录音需要安全上下文。** `http://` 的局域网地址（`http://192.168.x.x:5181`）在 Chrome 里
不算安全上下文，`getUserMedia` 会被直接拒绝 —— 看书、听音频都正常，**只有录音会失败**。
所以别走局域网 http。

`npm run build` → 把 `dist/` 拖到 EdgeOne Pages / Vercel / Cloudflare Pages，拿到
https 地址，平板 Chrome 打开、加到主屏。数据全在平板本地 IndexedDB，托管方只发静态文件。

临时调试也可以用 Chrome 的 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
把局域网地址加进白名单（每台设备手动配一次）。

构建用了 `base: './'`（相对路径），部署到任何子路径都不会白屏。

## 注意

- **没有关卡了。** 早先是三关闯关（听一遍 → 逐页跟读 → 整篇录音），必须按顺序过。
  实际用下来：读得好的书被迫走完三关，读不动的书卡在录音关退不回去，而「听」
  本该由孩子自己决定什么时候要。现在进书就是自由翻页，听/录/读完了都是随时可用
  的动作。**完成有两条路，都算读完**：点「读完了」，或者交了录音 —— 录音本身
  就是「我读给你听」，还要求他额外点一下没有意义。两条路都给变身（孩子最喜欢
  那一下）。听没听过、听了几遍都不影响完成。
- **读完之后绝不锁书。** 早先读完就把卡片禁用，结果当天想复习都打不开。现在只加
  一个「读完了 ✓」标记，照样能进去翻。
- **`PieceProgress` 里 `listened`/`pagesRead`/`browsed` 是关卡时代的遗留字段**，
  已不驱动任何界面，只用来给老记录推导 `finished`（见 `db.ts` 的 `loadProgress`）——
  不写迁移是有意的：推导比改写数据安全，孩子点过一次「读完了」就会存下真的 `finished`。
- **兼容推导要覆盖「中间那一版」，不能只看字段缺不缺。** 取消关卡但录音还不算读完
  的那一版已经会写下**显式的 `finished: false`**，所以 `if (finished === undefined)`
  根本不会触发 —— 那版交过的录音升级后会一直显示没读完。既然现在语义是「录音也算
  读完」，就对 `recorded` **无条件**补 `finished = true`。改语义时记得回头问一句：
  已经写进库里的数据会不会被新判断漏掉。
- **`loadDoneDates()` 要扫 `progress:` 取并集，不能只读 `done:` 键。** 盖章规则从
  「全部读完」放宽到「至少读完一本」之前，那些「只读完一两本」的日子根本没写过
  `done:`，光读键的话这些历史日期在日历和连续天数里永远是漏的。
- **打卡章只要「当天至少读完一本」。** 一天布置三四本、孩子读了两本也是读了，
  那天就该有章。章负责「这天有没有读」，「我的」页的 ✓/○ 负责「读了哪些」。
- **`lib/audio.ts` 是全 App 唯一的播放实现**，首页裸听 / 听这页 / 连着听 / 复习页
  都走它。「是哪本书」每次调用时传进去、不绑在 hook 上 —— 首页要能对任意一本书
  裸听，绑死一本的话切换时会用到上一次渲染留下的那本。顺序播放写两遍必然跑偏
  （早先 TTS 取消那个 bug 就是因为有两份，改了一处漏了另一处）。
- **连着听的 `onPage` 不能走 `turnTo`** —— `turnTo` 会 `stopPlay`，等于自己把自己
  掐断。它直接 `setIdx`。
- **阅读页中部的图片容器必须 `min-h-0`**（配 `object-contain`）。flex 子项的自动最小高度由内容决定，
  整页图会撑着不缩、溢出被裁 —— 裁掉的正好是页面底部那行字，而那行字就是孩子要读的内容。
- `packs/`、`build/`、`*.pdf`、`public/images/ultraman/`、`android/`、`out/` 都不入库
  （版权素材 / 可重新生成）。缺奥特曼图时走 `HeroImg` 的降级分支。
- **录音不会自动删。** 早先做过「评分后自动清理」，后来去掉了 —— 孩子的声音
  不该被 App 悄悄删掉。App 占地方变慢了，家长页「维护」里手动清（那里显示
  当前一共存了多少段、多大）。只清往日已评分的，今天的一律保留：家长可能
  刚打了分又想重听改分。
- 没做导出/备份 —— 单设备场景用不上，而且没有配套的导入，导出只会是个假的迁移。
- APK 里 `allowBackup="false"` 且排掉了 device-transfer：录音和 PIN 不该跟着
  任何系统自动流程走（这个项目的前提是零云服务）。
- 想复习旧书从「我的书架」进，走的是 `Review` 页：**不录音、不写进度**，免得复习污染当天打卡。
- **书架按书名去重**，同名以最新导入的为准 —— 一本书常要看好几天，每天的包里都有它，
  书架上却只该有一本。注意 `Map.set` 覆盖已有键时保留的是初次插入位置，所以必须显式按日期排序。
- **图和音频按内容哈希存（`blob:<sha256>`），任务包只存引用。** 同一本书连着
  好几天布置是常态（每周一本亲子共读的书天天带，高级别 RAZ 也会连读几天），
  按天各存一份的话一周白占 50 MB 且无上限增长。实测 3 个包 35.4 MB → 17.9 MB。
  三条安全性质，改之前先想清楚再动：
  1. **读取层同时认两种值**（Blob = v1 老包，字符串 = 哈希）。所以迁移可中断、
     可重跑：半迁移状态下 App 完全可用（已实测老格式包和新格式包的书都能开）。
  2. **迁移一天一个包地转**，转完立刻写回，峰值只多占一个包而不是翻倍。
  3. **删包绝不顺手删 blob** —— blob 是多天共享的，误删会静默弄没别的天的图。
     统一由 `gcBlobs()` 重算引用后再删没人引用的。**引用源必须是库里实际存在的
     `pack:` 键，不能是 `dates` 索引** —— 索引一漂（写索引前被杀、历史遗留），
     按索引统计就会漏掉一个真包、把它的素材当孤儿删掉。
  4. **迁移失败绝不能挡启动。** `reload()` 里 `await migrate()` 一旦抛异常，
     `ready` 就永远不置 true，App 卡在「载入中」，连家长页都进不去清理 —— 彻底锁死。
     现在 migrate 内部逐包容错、外面还包一层 try/catch，失败只在家长页给个提示；
     有失败就不升 `SCHEMA_VERSION`，下次打开自动重试（已转好的包会跳过，重试很便宜）。
- `listLibrary` 只读 manifest + 封面那一张图。早先它走 `loadPack`，等于为了列
  书架把近百 MB 素材全解析一遍。
- **`useSwipe` 拿不到视口宽度时要放行**，不能反过来把滑动全判无效 —— 边缘死区
  只是为了不跟系统手势抢，为它让孩子翻不动书是更糟的失败方向。（`innerWidth`
  在页面不可见时会是 0，就踩到过。）
- **翻页以左右滑动为主，箭头是辅助。** 孩子的小手点不准贴边的小箭头，而屏幕左右
  边缘（安卓 10+ 各约 20~24dp）是系统返回手势区、底部是 home 手势区 —— 误触会
  直接把阅读退出。所以 `lib/swipe.ts` 里**从边缘 44px 内起手的滑动一律忽略**
  （别跟系统抢），竖向位移大于横向也不算翻页（孩子常斜着划）；箭头同时从
  `left-1/right-1` 挪到 `left-4/right-4` 并放大到 h-14。
  **两个页面都要接** —— `Read`（阅读）和 `Review`（书架进去的复习）是两个独立
  组件、各有一套箭头，只改一个会漏（已经漏过一次）。
- **「我的」页切日期用 `day.date === picked` 作渲染条件**，不是 resolve 后才
  setDay —— 否则切换瞬间会把上一天的书单挂在新日期标题下面闪一下，顺带也挡掉
  「先点 A 又点 B、A 的结果后回来」的乱序。
- **「我的」页日历可点，和星星联动**：点哪天看那天读了什么、各得几星。
  用 `loadDaySummary()` 只读 manifest + 星星，**不碰图和音频** —— 回顾历史只
  需要书名，把那天的素材整包解析出来纯属浪费（一天可能十几 MB）。
