# 阅读打卡日记 — 架构设计（定稿）

定稿日期：2026-07-31
选型依据见 [技术调研.md](技术调研.md)

## 1. 关键决策

| 决策 | 结论 |
|---|---|
| 家长端要不要远程 | **不要**，同一台设备 → 零后端 |
| 孩子端设备 | **Android 平板** → Capacitor 打 APK |
| 素材录入 | **Mac 上跑 Claude Code skill**，把杂乱素材转成标准任务包文件，传到平板加载 |
| 第一关 | **只完整听一遍（可重听）即可继续，不出题、不设卡** |
| 孩子看什么读 | **绘本整页原图**，字本来就印在页面上，所以不抠图、不识别文字、不抄文本 |
| 跟读自动评分 | **不做**（免费方案不可靠），录音交给家长听 |

**由此得到一个重要简化：「家长端」不是一个 App，而是「一个 skill + 一个文件格式」。**
整个系统没有服务器、没有云存储、没有会过期的免费额度 —— 永久零成本。

## 2. 总体架构

```
┌─────────────────────────── 家长端（Mac / Claude Code）───────────────────────────┐
│                                                                                  │
│  skill：布置阅读任务                                                             │
│                                                                                  │
│  输入（家长手上有什么就给什么）                                                  │
│    · 带内嵌音频的 PDF 分级读物   → 抠每页真人音 + 渲染整页图（最理想，无需人工）  │
│    · 无音频的 PDF / 拍的课本     → 渲染整页图，朗读交给 App 的 TTS               │
│    · 纯文本 / 一段话             → 只给文本，App 用 TTS 朗读并显示               │
│    · 家长自己录的整段音频         → whisper-cli 转写+时间戳 → ffmpeg 切片        │
│                                                                                  │
│  处理：挑出正文页（排除封面 / 书名页 / 版权页）→ 组装                            │
│                                                                                  │
│  输出：一天一个任务包  YYYY-MM-DD.rdpkg                                          │
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   │  网盘 / 微信 / USB（纯文件传输，本来就免费）
                                   ▼
┌────────────────────── 孩子端 + 家长模式（同一个 Android APK）────────────────────┐
│                                                                                  │
│  导入：扫描下载目录发现 .rdpkg（或按钮选文件）→ 解包 → 存 IndexedDB              │
│                                                                                  │
│  孩子端（主界面）  每篇任务走三遍法：                                            │
│    第一关 完整听一遍（可重听）→ 继续，不出题不设卡                              │
│    第二关 逐页领读（每页一个播放键）→ 孩子跟读                                  │
│    第三关 整篇朗读 → MediaRecorder 录音 → 存 IndexedDB                          │
│    完成 → 打卡日历 + 连续天数                                                    │
│                                                                                  │
│  家长模式（PIN 码进入）                                                          │
│    听孩子录音 → 打 5 颗星评分 → 孩子端「我的反馈」页展示                        │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 任务包格式 `.rdpkg`

本质是一个 **zip**（换个后缀便于 App 扫描下载目录时识别）。前端用 JSZip 解包。

**核心简化：绘本每页本来就印着文字，所以不抠图、不识别文字、不抄文本。**
包 = 整页原图 + 每页音频，孩子直接看原书页，字就在图上。

以下为已跑通的真实结构（`packs/2026-08-01.rdpkg`，2.6 MB，2 篇 18 页全真人音）：

```
2026-08-01.rdpkg
├── manifest.json
├── audio/
│   ├── p1-s0.mp3 … p1-s7.mp3     # 第 1 篇每页音频
│   └── p2-s0.mp3 … p2-s9.mp3     # 第 2 篇
└── images/
    ├── p1-cover.jpg, p1-s0.jpg … # 整页原图，宽 900px
    └── p2-cover.jpg, p2-s0.jpg …
```

### manifest.json

```json
{
  "format": "reading-diary-pack",
  "version": 1,
  "date": "2026-08-01",
  "child": "",
  "pieces": [
    {
      "id": "p1",
      "title": "All Kinds of Faces",
      "lang": "en-US",
      "level": "RAZ Level A",
      "listen": { "mode": "sequence" },
      "pages": [
        { "image": "images/p1-s0.jpg", "audio": "audio/p1-s0.mp3" },
        { "image": "images/p1-s1.jpg", "audio": "audio/p1-s1.mp3" }
      ],
      "cover": "images/p1-cover.jpg"
    }
  ]
}
```

### 字段约定

| 字段 | 说明 |
|---|---|
| `pieces` | **一天一个包，一篇一个 piece**，篇数不限。包内文件名带 `id` 前缀，多篇不串台 |
| `lang` | `zh-CN` / `en-US`，只在需要 TTS 时决定音色 |
| `listen.mode` | `"sequence"` = 第一关依次播放各页音频作为"听一遍全篇" |
| `pages[].image` | 整页原图，孩子读这页时显示 |
| `pages[].audio` | 该页真人音频。**`null` 表示这页用 TTS 朗读，此时需要 `text`** |
| `pages[].text` | **仅在没有真人音频时才需要**，供 TTS 朗读 |
| `cover` | 可选，书的封面图 |

**一天一个包**，而不是一篇一个包：业务单位是"天"（打卡、录音回传都按天），
孩子只需导入一次，App 也不用去拼"今天到底布置了几个包"。

## 4. 免费能力清单（全部本地、无 API、无额度）

| 能力 | 方案 | 状态 |
|---|---|---|
| PDF / 扫描件读文本 | Claude Code `Read` 工具原生支持 | ✅ 现成 |
| 拍照课本读文本 | Claude 直接看图 | ✅ 现成 |
| 中文/英文 TTS | 系统内置语音（`speechSynthesis` / Capacitor TTS） | ✅ `orange_read/src/lib/tts.ts` 可直接抄 |
| 家长录音逐句切分 | `whisper-cli -l zh -oj` 出时间戳 + VAD 静音切分 → `ffmpeg` 切片 | ⚠️ 二进制已装（ffmpeg 8.1 + whisper-cli），**ggml 模型需一次性下载** |
| 孩子录音 | `MediaRecorder`（Android 上稳定） | ✅ |
| 页面图 | 从 PDF 直接渲染整页（含原书文字），无需图库 | ✅ |
| 打包成 APK | Capacitor | ✅ `orange_read/android/` 配置可抄 |
| 阅读进度/打卡 | `orange_read` 的 `useReadingTracker` | ✅ 可抄 |

**whisper 模型建议**：中文用 `ggml-small`（~460MB）或 `ggml-medium`（~1.5GB）效果明显好于 `base`。
只在家长有真人录音素材时才需要；纯 TTS 路线完全不需要下模型。

## 6. 已定的细节

| 细节 | 结论 |
|---|---|
| `.rdpkg` 导入方式 | **按钮 + 系统文件选择器**（永久保留作兜底）**＋ App 自动扫描下载目录**，发现新包就在首页提示一键加载。**不做安卓文件关联** —— 要动原生层处理 `content://` URI，且 `.rdpkg` 自定义后缀常被网盘报成 `application/octet-stream`，会让 App 去抢所有未知类型文件 |
| 家长反馈形式 | **只做 5 颗星评分**。家长模式在 APK 内，录语音只能在平板上录，而家长既然在场，当面鼓励比录音更自然 |
| 第一关是否设卡 | **不设**。原设计是"三选一图片答对才过关"，已取消 —— 听一遍就能继续，想再听可以重听 |
| whisper 模型 | **先不下**。分级读物音频本来就是每页一句（实测 1.6~1.8 秒/句），粒度正好；只在"家长整段连续录音需切句"等情况才需要，见 skill 文档 |

## 7. 家长端 skill 已就绪

`.claude/skills/reading-pack/` —— 详见 [SKILL.md](../.claude/skills/reading-pack/SKILL.md)

- `scripts/extract_pdf.py` —— 抠每页内嵌音频 + 渲染整页图（支持 RichMedia 和 Screen/Rendition
  两种内嵌音频做法，并交叉校验页码与音频文件名是否错位）
- `scripts/build_pack.py` —— 按 plan.json 组装 `.rdpkg`（零第三方依赖）

已用两本 RAZ Level A 跑通，合成**一个** `packs/2026-08-01.rdpkg`（2.6 MB）：

| 篇 | 书 | 内嵌方式 | 正文页 | 真人音 |
|---|---|---|---|---|
| p1 | All Kinds of Faces | RichMedia 注释 | 3–10（8 页） | 8/8 |
| p2 | Bird Colors | Screen 注释 + Rendition | 3–12（10 页） | 10/10 |

⚠️ 踩过的坑：解析 annot 对象图时**不能跟随 `/P` 和 `/Parent`**，否则会从本页逃进整个
页面树、摸到别页的音频，导致页与音频错位（孩子会听着 A 页的音读 B 页的字）。
已在 `extract_pdf.py` 里剪掉这两个键，并加了页码/文件名交叉校验兜底。
