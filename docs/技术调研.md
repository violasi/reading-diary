# 阅读打卡日记 — 技术调研（全免费自用）

调研日期：2026-07-31

## 0. 需求回顾

- **家长端**：每天布置阅读任务，篇数不限；收孩子录音；给评分
- **孩子端**：每篇任务走「三遍法」
  - 第一关：完整听一遍素材（可重听），听完即可继续
  - 第二关：领读 —— 逐页可点播，孩子跟读
  - 第三关：孩子自己完整读一遍，录音
- 一天任务结束后，录音回传家长端

> 需求在同日调整过两处，本文后续章节均已按调整后的版本：
> ① 第一关原为"三选一图片答对才过关"，改为**只听不考**；
> ② 家长反馈原含语音，改为**只给 5 颗星评分**（家长在场，当面鼓励更自然）。

## 1. 核心判断：这个项目唯一的新技术难点是"跨设备数据流"

工作区里三个前作都是**纯前端 + 本地存储、零后端**：

| 项目 | 形态 | 存储 | 托管 |
|---|---|---|---|
| `orange_read`（奥特曼日记） | React 19 + Vite 8 + Tailwind 4 + Capacitor(Android) | IndexedDB | EdgeOne Pages（`ultraman-ai-read.edgeone.dev`） |
| `family_reader` | React + Vite | 本地 | — |
| `reading_hour`（阅读时光） | 微信小程序原生 | 本地，**没用云开发** | 小程序 |

而本项目要求「家长布置 → 孩子做 → 录音回传 → 家长评分」，是**两个人、两台设备、双向流转**。
纯 IndexedDB 做不到。**所有选型分歧都收敛到一个问题：家长端要不要远程。**

其余部分（阅读 UI、TTS、主题化、Capacitor 打包）在 `orange_read` 里全都有现成实现可复用。

## 2. 方案对比

### 方案 A：单设备双角色（零后端，永久免费）

- **形态**：一个网页/PWA。孩子端是主界面；家长入口用 PIN 码进（`/parent`）
- **家长操作**：在孩子的平板上布置任务、当场或事后听录音、评分
- **存储**：全部 IndexedDB（录音以 Blob 存本地）
- **托管**：EdgeOne Pages 免费子域，或干脆纯本地打开
- **成本**：0，且**没有任何会过期的免费额度**
- **代价**：家长必须拿到孩子的设备，无法远程。数据在单一设备上，清缓存即丢（需导出备份 —— `orange_read` 已有这套导出逻辑）

> 适合：家长孩子每天同处一室（大多数小学低年级家庭其实是这种）

### 方案 B：EdgeOne Pages + KV + Blob（推荐，真双端）★

- **形态**：同一个前端两个路由。家长端手机浏览器开 `/parent`；孩子端平板开 `/kid`
- **后端**：EdgeOne Edge Functions / Cloud Functions + KV（任务、评分等元数据）+ Blob（录音文件）
- **免费版配额**（已核实，来源：腾讯云 EdgeOne Makers 限制与配额文档）：

  | 项 | 免费版 |
  |---|---|
  | KV 存储空间 | 1 GB（单值上限 1 MB） |
  | Blob 存储空间 | 1 GB |
  | Edge Functions 执行次数 | 300 万/月 |
  | Cloud Functions 执行次数 | 100 万/月 |
  | 构建次数 | 500 次/月 |
  | 项目数 | 40 个 |
  | 请求 body 大小 | 1 MB |

- **容量算账**：一段 30s 录音（Opus ~24kbps）≈ 90 KB。按每天 3 篇、每篇 1 段录音 ≈ 270 KB/天 ≈ 100 MB/年。
  1 GB Blob 够用约 9 年；家长评分后自动清理老录音的话，等于用不完。
  ⚠️ 注意「请求 body ≤ 1 MB」：单段录音要控制在 1 MB 内（30s Opus 没问题，但长录音需切片上传或压码率）
- **国内可直连、用 `*.edgeone.dev` 免费子域免备案**，且你已经在用这个平台
- **风险**：官方明示免费版处于**商业化之前**，"商业化后配额可能调整"。目前政策是超限也优先保业务稳定

### 方案 C：微信小程序 + 云开发（❌ 通不过"全免费"）

- **优点**：家长孩子都在微信里，能发订阅消息提醒；`wx.getRecorderManager` 录音成熟；iPad 微信也能跑
- **致命问题**（已核实，来源：微信开放社区计费说明）：
  - 免费云环境**仅在小程序未发布上线阶段免费**；小程序一发布，环境到期时间改为**上线后第 15 天**
  - 之后需转付费：基础套餐 **19.9 元/月**（原价 39 元/月）
  - 该免费活动**截止 2026-12-31**，之后可能调整
- 只有「永不发布、长期只用体验版」才能白用，但那是在钻政策空子，随时会变
- 你的 `reading_hour` 虽是小程序，但没接云开发，帮不上这次的双端同步

### 方案 D：家里电脑自建 + 内网穿透

Mac/旧电脑跑个 Node 服务，孩子平板局域网访问。免费、数据全在自己手里，但**要求电脑常开机**，出门就用不了。可作为方案 B 的兜底。

## 3. 各端具体形式建议

### 孩子端

| 设备 | 建议形式 | 说明 |
|---|---|---|
| **Android 平板**（最优） | Capacitor 打 APK | 直接复用 `orange_read/android/` 那套配置；原生录音权限稳定；全屏无浏览器干扰 |
| **iPad / iPhone** | Safari **标签页**，别加到主屏 | ⚠️ 已知问题：iOS 上「添加到主屏」的独立 PWA 模式下 `MediaRecorder` 有 bug —— 第一次能录，关掉再开就录不了，需重启手机才恢复（Safari 标签页里则正常）。若坚持要主屏图标，需改用原生封装 |
| 电脑 | 浏览器直接开 | 最省事，但小孩用电脑体验一般 |

### 家长端

**手机浏览器网页就够，不需要做 App。** 布置任务、听录音、打分都是低频轻交互。
加到主屏做个图标即可（家长端不录音，不受上面那个 iOS bug 影响）。

## 4. 三遍法的技术拆解与免费实现

### 第一关：完整听一遍

- 只是听，不出题、不设卡，听完（或重听）即可进第二关 —— 零判定逻辑
- **素材音频**优先用素材自带的真人音（分级读物 PDF 每页内嵌了真人朗读，skill 能直接抠出来）；
  没有真人音时退化为 TTS，零成本：`orange_read/src/lib/tts.ts` 已封装好双通道
  - 原生（Capacitor）：`@capacitor-community/text-to-speech`
  - 浏览器：`window.speechSynthesis`（系统内置中英文音色，离线、免费、无限量）

### 第二关：领读 + 跟读

- **粒度按页**：分级读物一页就是一句，页面图和音频都是按页给的，不需要再做分句
  （素材是纯文本、必须自己切分时，中文按 `。！？；\n` 正则分句即可）
- **每页一个播放按钮** → 播真人音，没有则调 TTS，零成本
- **跟读**：如果只是"孩子跟着念、不判分"，零成本
  ⚠️ 如果想**自动评测发音准确度**（打分、标出读错的字），免费方案基本没有：
  - 微信同声传译插件的语音识别绑定小程序生态，且回到方案 C 的收费问题
  - 浏览器 `SpeechRecognition` 在 iOS Safari 上支持差，且识别结果做发音评分很不可靠
  - **建议**：第二关不做自动评分，第三关的录音交给家长听 —— 这也正是需求里「家长评分」的设计

### 第三关：完整录音

- `MediaRecorder` → Blob → 上传（方案 B）或存 IndexedDB（方案 A）
- 编码优先 `audio/webm;codecs=opus`；iOS Safari 只给 `audio/mp4`，需要按 `MediaRecorder.isTypeSupported` 做降级

## 5. 结论

- **想要"永久零成本、零风险"** → 方案 A（单设备双角色）
- **想要"家长能远程"** → 方案 B（EdgeOne KV + Blob），当前完全免费、国内直连、平台你已在用；唯一风险是免费版商业化后配额可能变
- **不要走微信小程序 + 云开发**，它在"全免费"这条约束下过不了关
- 孩子端优先 Android 平板 + Capacitor；只有 iPad 的话用 Safari 标签页，避开 iOS PWA 录音 bug
- 家长端网页即可
- TTS、阅读 UI、Capacitor 打包、导出备份 —— 全部可从 `orange_read` 复用
